# Architecture Decision Record (ADR)

Note: Normative rules live in `CLAUDE.md`. This ADR records a change to one of them (the iOS guardrail).

## Title
ADR: iOS shell v1: minimal SwiftUI + WKWebView, Xcode project as source of truth

## Date
2026-10-08

## Status
Accepted

## Context
The Oct 2025 iOS scaffold (XcodeGen spec, AppCoordinator, native Debug tab, KVO progress bar,
pull-to-refresh, a replaced user agent) predates what Pare is now: a fixed web app shell with its
own 5-tab nav, live at pare.gg, that already handles safe areas and hides its footer when the UA
contains `Pare-iOS`. The scaffold fought the web shell (two tab bars, bounce + refresh gestures the
web rules out), and the generator added a tool Kobe doesn't otherwise use. Xcode 26 synchronized
folders remove the main reason for a generator (hand-maintained file lists in the pbxproj).

## Decision
Ship a **minimal SwiftUI + WKWebView shell** that loads https://pare.gg: 6 Swift files, a privacy
manifest and an `Info.plist` with extra keys only. **`ios/Pare.xcodeproj` is the source of truth**,
created and edited only in the Xcode UI, with sources in the synchronized folder `ios/Pare/`.
The web talks to the app only through an allow-listed one-way bridge (`share`, `haptic`, `openSettings`).

## Consequences
- + Feels native where it matters (no white flash, no rubber-band, Safari sheet for external links,
  offline screen, Settings sheet) with no duplicate navigation.
- + No generator: any file in `ios/Pare/` builds; the project opens straight from git.
- + The web needs no change or deploy: the UA token `Pare-iOS` already matches `lib/platform.ts`.
- − Project settings live in a pbxproj that's only safe to edit in Xcode, so Mac-side steps are
  human gates (H1/H2/H3/S) with a written checklist in `ios/README.md`.
- − App Store guideline 4.2 rejects plain web wrappers. v1 is a foundation, not a submission:
  native Settings, share, haptics and offline help, but push or widgets are likely needed.
  Blockers are tracked in the dev note.
- − Bundle ID is `gg.pare.app.dev` on a Personal Team until Pare LLC enrollment is approved
  (Phase S), so the real ID stays claimable.

## Alternatives Considered
- **Keep the 2025 scaffold** — already built, but its native tab bar and gestures conflict with the
  web shell, and it depends on a generator. Rejected.
- **Capacitor / PWABuilder** — fast and adds a plugin ecosystem, but brings a JS toolchain and
  config layer into a repo that only needs ~400 lines of Swift. Rejected for v1.
- **Native SwiftUI app** — best App Store story, but rebuilds every screen. Deferred
  ("WKWebView wrapper now, native later").
