# Dev Note — 2026-09-14 — 2026 season switch + live OFFENSE stats from ESPN

> Rules & architecture live in `CLAUDE.md`; this note is implementation rationale only.
> State authority: `CHANGELOG.md` `[Unreleased]`.

## Context
Stop reading offense from the static 2025 CSV. Pull live **2026** offense team
totals from ESPN and map them into the SAME `TeamStats` shape the app already
consumes, so ranking / display-mode / bar hooks and the UI stay untouched.

Scope guardrails for this step (Step 2):
- **OFFENSE only.** DEFENSE stays on the CSV path (Steps 3–4 handle it — the
  yards-allowed gap is documented in `DATA_SOURCES.md`).
- Do **not** touch schedule or compare UI.
- No new dependencies. TypeScript, no `any`. Don't change hook signatures or the
  `TeamStats` shape.

## Decisions
- **Season constant**: `APP_CONSTANTS.SEASON = 2026` (`config/constants.ts`). Used
  wherever a season year is needed. The `nfl-2025` route **folder** name is left
  as-is on purpose — renaming the URL is a later cosmetic cleanup.
- **ESPN team IDs live on the team registry**: added `espnId` to `NflTeam` +
  every entry in `lib/teams.ts` (map from `DATA_SOURCES.md §3`). Lets us loop all
  32 teams by id and map each back to the app's team key (full name).
- **New fetcher, not a parser edit**: `lib/espnStats.ts` →
  `fetchOffenseStatsFromESPN()` rather than overloading `lib/pfrCsv.ts`. Keeps the
  CSV reader intact for the defense fallback + defense route.
- **Season TOTALS, not perGame**: we map the stat `value` (season total); the app
  computes per-game itself (`useDisplayMode`). Values stored as **strings** to
  match the CSV parser output exactly.
- **Endpoint**: per-team
  `.../seasons/{SEASON}/types/2/teams/{ESPN_TEAM_ID}/statistics`, all 32 in
  parallel (`Promise.all`), each with an 8s abort timeout. Cached by the route's
  existing in-memory cache (no per-fetch caching layer added).
- **Field mapping** (clean 1:1 only): `g←gamesPlayed`, `points←totalPoints`,
  `total_yards←totalYards`, `pass_yds←passingYards`, `rush_yds←rushingYards`,
  `pass_cmp←completions`, `pass_att←passingAttempts`, `pass_td←passingTouchdowns`,
  `pass_int←interceptions`, `plays_offense←totalOffensivePlays`,
  `first_down←firstDowns`, `rush_att←rushingAttempts`, `rush_td←rushingTouchdowns`,
  `fumbles_lost←fumblesLost`, `turnovers←totalGiveaways`.
  Stats are flattened across all `splits.categories[]` (first occurrence wins),
  so a stat's category doesn't matter.
- **Unpopulated metrics** (no clean ESPN source — e.g. `score_pct`, penalties,
  `exp_pts_tot`) are left off the row. The existing rows coerce a missing value to
  `'0'`, so they render `0.0%` / `0` with even bars — **no crash**. A true `—`
  empty-state was deferred so we don't touch the sacred compare rows this step
  (see follow-ups). `score_pct` mapping is explicitly the next (Sc%) step.

## Wiring / Resilience
`app/api/nfl-2025/offense/route.ts`:
1. Cache HIT → serve cache (unchanged).
2. Fresh → `fetchOffenseStatsFromESPN()` (`X-Source: ESPN`).
3. ESPN fails / `<32` teams → serve **stale cache** if present (`X-Source: ESPN-STALE`).
4. No cache → fall back to `fetchAndParseCSV({ type:'offense' })` 2025 CSV
   (`X-Source: CSV-FALLBACK`, response flagged `stale`).
5. CSV also gone → outer catch → 500.
Only a full live ESPN result is written to cache (never the CSV fallback).
Each path logs which source served.

`defense/route.ts`: unchanged (CSV, season 2025).
