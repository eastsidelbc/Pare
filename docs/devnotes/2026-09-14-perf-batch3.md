# Dev Note — 2026-09-14 — Data caching, Batch 3

Rules & architecture live in [`CLAUDE.md`](../../CLAUDE.md); this note is rationale only.
Follows [Batch 1](./2026-09-14-perf-batch1.md) + [Batch 2](./2026-09-14-perf-batch2.md).
Implements audit item `#1`.

## Problem
All ESPN fetches used `cache: 'no-store'`, opting out of Next.js's Data Cache.
The defense yards aggregation (`fetchDefenseYardsAllowed`) issues 80+ HTTP requests
(scoreboard per week + summary per completed game) every time a cold serverless
lambda handles a defense API request — potentially many seconds and 100s of calls
per hour across concurrent instances.

## Changes

### `config/constants.ts` — `REVALIDATE_SECONDS: 3600`
Single tunable for the Next.js Data Cache window. All ESPN fetch and route-cache
durations reference this value.

### `lib/espnStats.ts` — remove `cache: 'no-store'`, add `unstable_cache`
- `fetchOneTeam` (offense stats): `cache: 'no-store'` → `next: { revalidate: REVALIDATE_SECONDS }`.
- `fetchDefenseStatsFromESPN` (standings): same.
- `fetchJsonWithTimeout` (scoreboard + game summaries): same. This covers all
  `getFinalEventIds` and `getGameYards` calls used by the yards aggregation.
- Renamed the implementation to `_fetchDefenseYardsAllowed` (private) returning
  `Record<string, YardsAllowed>` (JSON-serializable for `unstable_cache`).
- Added `_cachedFetchDefenseYardsAllowed = unstable_cache(_fetchDefenseYardsAllowed,
  ['defense-yards-allowed', String(SEASON)], { revalidate: REVALIDATE_SECONDS, tags: [...] })`.
- Public `fetchDefenseYardsAllowed()` now calls the cached version and wraps the
  `Record` back into a `Map` — call site in `defense/route.ts` is unchanged.

**Effect on `fetchDefenseYardsAllowed` at runtime:**
- Cache miss (first call / revalidation): full aggregation runs (80+ fetches, each
  served from the Next.js Data Cache on the second and subsequent calls within the
  revalidate window), result written to `unstable_cache`.
- Cache hit: only the `new Map(Object.entries(obj))` wrapper runs — the aggregation
  and all ESPN calls are skipped entirely.

### `app/api/nfl-2025/offense/route.ts` — `export const revalidate = 3600`
### `app/api/nfl-2025/defense/route.ts` — `export const revalidate = 3600`
Route-level revalidation caches the complete HTTP response. Build output confirms:
- `/api/nfl-2025/offense` → `○ Static · Revalidate: 1h, Expire: 1y`
- `/api/nfl-2025/defense` → `○ Static · Revalidate: 1h, Expire: 1y`

Note: literal `3600` required (Turbopack's static analysis can't resolve imported
constants for segment config exports). Comment links to `REVALIDATE_SECONDS`.

### `/api/schedule` — unchanged at route level
Reads `week` query param → must remain `ƒ Dynamic`. Fetch-level caching inside
`lib/schedule.ts` (`next: { revalidate: REVALIDATE_SECONDS }`) handles it.

### `lib/schedule.ts`
Hardcoded `3600` in `fetchScoreboard` tied to `APP_CONSTANTS.CACHE.REVALIDATE_SECONDS`.

## Retained behaviors
- Graceful fallback (stale in-memory cache → empty rows) in both routes: unchanged.
- 8s fetch timeouts in `fetchOneTeam` / `fetchJsonWithTimeout`: the abort signal
  still fires for uncached (first-ever) requests; cached responses are served
  without a network call so the signal is irrelevant.
- Defense route still enriches with yards-allowed best-effort; yards aggregation
  errors still fall back to points-only rows.

## Verification
- `npm run build` → exit 0, no errors. Route table shows `○ Static · 1h` for both
  API routes.
- No `cache:'no-store'` remains in `lib/espnStats.ts` (grep confirmed).
- `unstable_cache` and `next.revalidate` confirmed at 3 fetch sites + aggregation wrapper.
- Defense endpoint: 38ms → 35ms on consecutive curls (no re-aggregation).
- REVALIDATE value: **3600 seconds (1 hour)**.
