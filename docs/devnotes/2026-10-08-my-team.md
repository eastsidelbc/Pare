## What My Team is (one paragraph)

A 5th nav tab, **Fantasy** (`/myteam`). The user types a Sleeper username, picks a league, and sees each rostered player's NFL matchup as a 5-bar meter (Avoid → Great, ranked by fantasy points allowed per game under the league's own scoring), a 5-week look-ahead, injury tags, Start / Sit by matchup ("not a projection"), Open in Compare, and live points on game day. It assists the user's league app; it doesn't replace it (no lineup moves, no big total, no opponent score).

### Privacy decisions (for Kobe's wording review)

Each claim on `/privacy` was checked against the code before writing it:

- **Device never talks to Sleeper.** `MyTeamProvider` and `useMyTeamLive` only fetch `/api/myteam/{user,league,live}`. Sleeper calls are all in `lib/myteam/sleeper/http.ts` (server-only) and `lib/fantasy.ts`.
- **"Never written to disk, never logged."** Per-user data lives only in `createKeyedCache` (memory). `unstable_cache` holds shared data only (stat lines, schedule, player map). The one `console.error` (`lib/myteam/apiErrors.ts`) logs the error message, and `sleeperJson` errors never contain the URL.
- **"Deleted automatically within 2 days of your last use."** Fixed in the P7 follow-up: `createKeyedCache` never deleted expired entries (expired = still held as last-good), so the first wording ("up to 24 hours") was false. **Retention** = no entry outlives 2 × TTL (`createKeyedCache` sweeps every min(10 min, TTL/2) on an unref'd timer and deletes entries older than 2 × TTL − that interval; last-good kept ≥1.5 × TTL) — exactly 48h max for the username lookup, ≤2 min for live points — for App Store guideline 5.1.1(i)/(iii). App Privacy label: **User ID · App Functionality · Linked · not used for tracking**. A cache hit doesn't reset an entry's clock, so 2 days is counted from the last fetch, which is never later than the last use.
- **Why the sweep interval scales with TTL:** a fixed 10-min sweep overshoots the promise by up to 10 min (48h10m), and a fixed `2 × TTL − 10 min` cutoff goes negative for short TTLs (matchups 60s) and would delete fresh entries. Sweeping every min(10 min, TTL/2) and cutting at `2 × TTL − interval` gives an exact 2 × TTL ceiling for every cache. Cost: short-TTL caches (matchups, rosters, shared ESPN data) keep last-good for 1.5–2 × TTL instead of 2 × TTL + up to 10 min; live points also keep last-good client-side (`liveReducer`).
- **Requests carry** the username, then the Sleeper user ID and league ID (`/api/myteam/{user,league,live}` query strings) — `/privacy` names all three.
- **Cloudflare sees the username** because it's in the query string (P2 devnote gotcha). Stated plainly rather than hidden. The alternative (POST body) is a data-layer change; not worth it for public Sleeper handles.
- **Removal:** "Change username" in the league sheet runs `unlinkAccount` (clears username, user id, league id; keeps the Season/Last 4 choice). The policy text lists it alongside "clear your browser data".
- **Sleeper "non-commercial" + "Sleeper's own privacy policy"** are named but not linked: Kobe verifies Sleeper's terms (F7) and can add the link then.
