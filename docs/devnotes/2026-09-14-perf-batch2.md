# Dev Note — 2026-09-14 — Compare perf, Batch 2

Rules & architecture live in [`CLAUDE.md`](../../CLAUDE.md); this note is rationale only.
Follows [Batch 1](./2026-09-14-perf-batch1.md). Implements audit item `#3`.

## Changes

### Windowing (active ±1)
`CompareWorkspace` previously mounted a `<ComparePane>` for every comparison
(up to `MAX_COMPARISONS = 8`). Now the map computes
`isWindowed = Math.abs(i - activeIndex) <= 1` and only mounts the active pane and
its two neighbors; other cells render as an empty `<div>` of the same width, so:
- the flex track width and `dragConstraints` are unchanged;
- a swipe always reveals an already-mounted neighbor (no blank flash mid-swipe);
- panes ≥2 away are virtualized (not mounted).

**Snap refinement:** the snap `useEffect` now compares against `prevIndexRef`. A
non-adjacent jump (tab tap across >1 page) sets `x` instantly instead of
spring-animating, because a long slide would scroll the track past unmounted
(empty) cells. Adjacent moves (swipe / neighbor tap) still spring smoothly.

**Tradeoff:** a pane ≥2 away unmounts, so its transient local state (per-panel
display-mode toggle in `useDisplayMode`) resets to `per-game` on remount. The
active pane and immediate neighbors always keep their state. This is inherent to
virtualization and matches the batch's explicit ask.

### React.memo
Wrapped in `React.memo`: `ComparePane`, `OffensePanel`, `DefensePanel`,
`CompactPanel`, `MobileCompareLayout`, `DynamicComparisonRow`,
`CompactComparisonRow`. Context consumers (theme, display mode) still update
normally — `memo` only shallow-compares props.

To make the row-level memo actually effective, the per-team transforms
(`transformTeamData(...)`) are now memoized in `OffensePanel`/`DefensePanel`/
`CompactPanel` (they previously produced a new object identity every render and
would have forced every row to re-render). `CompactPanel`'s `handleTeamAChange`/
`handleTeamBChange` are now `useCallback`-stable.

### Stable per-pane handlers
`CompareWorkspace` built fresh `(t) => updateComparison(c.id, …)` closures for
every pane on every render, which would defeat `memo(ComparePane)`. Replaced with
a per-id handler cache (`paneHandlersRef` + `getPaneHandlers`) whose closures call
`updateComparison` through `updateRef` (a ref kept in sync via effect). Handler
identity is therefore constant per comparison id, so an unrelated `setActive`
(which changes `activeId` but not the `comparisons` array) no longer re-renders
the other panes.

## Verification (cheap, no browser)
- `npm run build` → exit 0, no errors (only the same pre-existing `no-unused-vars`
  warnings as before).
- Code walk-through of the acceptance points:
  - Swipe reveals neighbors: `isWindowed` keeps active ±1 mounted; drag is a
    transform on `x`; committing a swipe shifts `activeIndex` by 1, so the new
    active + neighbors were already mounted → no blank.
  - Tab switch shows correct teams: `setActive(id)` updates `activeIndex` → target
    becomes windowed/mounted in the same render; non-adjacent snaps instantly.
  - Close works: `removeComparison` reassigns active to a neighbor; the `memo`d
    `ComparePane` for each remaining id keeps its correct teams (props unchanged).
