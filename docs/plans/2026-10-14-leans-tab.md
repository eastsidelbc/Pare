## Context

Pare gets a fifth tab, **Leans** (lucide `Scale`), in Standings' nav slot. It shows this week's games
with their lines (spread · total · moneyline) and a data lean per line, plus user-typed prop lines
checked against the player's game log and the defense's matchup tier. A lean shows only when
**3 signals agree** (DECISIONS §6); every screen shows the 3 checks. Nothing is a bet: no odds feed,
no sportsbook names/logos, lines typed by the user stay in `localStorage`, and every Leans screen
carries the responsible-gambling footer.

Standings stays exactly as it is and opens from a new 44px `ListOrdered` button in the Home header.

## Design

**Data (server, `lib/leans/bundle.ts`, `server-only`).** One shared copy (10 min, `createKeyedCache`):
current season/week, completed weeks, `teamLog` (team, opp, week, points, pointsAllowed — all 32),
`defenseLog` (for why-stats), an FPA table for QB/RB/WR/TE scored as Sleeper PPR, every
prop-eligible player (QB 2 · RB 3 · WR 5 · TE 3 per team by season PPR) with their weekly
prop stats, and the season schedule. `GET /api/leans/data?teams=ATL,LV` returns the shared parts +
only the requested teams' players and schedule. Raw values only — **ranking runs client-side**
(`rankAll`, `rankFpa`). Never nests caches (pieces keep their own `unstable_cache`).

**Lines (`lib/espnScoreboard.ts`).** `MatchupOdds` gains optional `spreadLine { team, line }` and
`moneyline { away, home }` (American odds as numbers), parsed from `odds[0].details` and
`odds[0].moneyline.{away,home}.close.odds` (fallback `.open.odds`). The `spread` string stays, so
Home renders identically.

**Lean engine (pure, `lib/leans/*`).** Shared result type:
`{ verdict: 'over'|'under'|'side'|'none'|'not-enough', side?: 'away'|'home', signals: { ok, label }[] }`
(labels mark bold parts with `**…**`). Only games **before** the game's week count, so a past
week shows the lean as it stood before kickoff. Thresholds live in `lib/leans/config.ts` only.

| Line | Signal 1 | Signal 2 | Signal 3 |
|---|---|---|---|
| Prop OVER (UNDER mirror) | over the line in ≥3 of last 4 (≤1) | ≥60% of games this season (≤40%) | matchup tier Good/Great (Tough/Avoid), Season window |
| Total OVER (UNDER) | both offenses top-10 (bottom-10) in points/game, last 4 | each team's last-4 game totals average above (below) the line | over (under) hit in ≥3 of 4 for both teams |
| Spread side S | last-4 avg margin gap ≥ 8 pts toward S | season point-differential rank ≥ 10 places better | S would have covered today's line in ≥3 of last 4 **and** the other side ≤1 of 4 |
| Moneyline side S | same as spread 1 | same as spread 2 | S won ≥3 of last 4 **and** the other side ≤1 of 4 |

Spread / ML are deliberately conservative (three independent team-data reads that must all point
the same way) — expected to be rare, per DECISIONS §6. <4 games for the player (props) or either
team (game lines) → **"Not enough games yet"**. Anything else → **"No lean"**.

**Props (`lib/leans/propStore.ts`).** `localStorage` key `pare:leans-props:v1`, versioned envelope
`{ v: 1, props: SavedProp[] }`; every read/write in try/catch (private mode / quota / corrupt JSON →
empty list, never a crash). Nothing leaves the device (the `/api/leans/data` request carries team
abbreviations only). /privacy lists the new key.

**Routes.** `/leans` (list) · `/leans/[gameId]` (G2 game screen; id = the existing `Matchup.id`,
e.g. `2026-w7-ATL-LV`) · `/leans/prop/[propId]` (prop detail) · `/leans/player/[playerId]?game=` (player
vs defense) · `/api/leans/data`. Every `/leans` route renders `LeansFooter`.

## Risks

- **ESPN odds are unofficial** (DATA_SOURCES). A missing `moneyline` object → that cell shows "—", the ML row shows "No lean". Parsing is fixture-tested.
- **Cold player map** (`getPlayerMap`, ~20 MB from Sleeper) can make the first `/api/leans/data` slow after a deploy; it's already warmed by Leaders. On failure the picker is empty and the props section says so — game lines still work (they only need ESPN).
- **Week-1–4 thin data**: most leans read "Not enough games yet" until week 5. Expected, stated in copy.
- **MatchupCard reuse via a wrapper class**: the list card keeps Home's card file untouched; a CSS rule scoped to `.leans-frame` strips MatchupCard's own frame so one Leans frame wraps the whole card. If MatchupCard's frame markup changes, this rule must follow (noted in the component comment).
- **Spread/ML rules are new inventions** (DECISIONS asked the plan to propose them). Conservative on purpose; thresholds in one file.
- **Responsible-gambling copy** is enforced by a test, not by review alone.
