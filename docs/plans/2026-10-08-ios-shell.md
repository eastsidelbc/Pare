## Context

The Oct 2025 iOS scaffold (XcodeGen spec, AppCoordinator, Debug tab, KVO progress bar, pull-to-refresh, `customUserAgent`) doesn't match what Pare is now: a fixed app shell with its own 5-tab web nav, live at pare.gg. Kobe chose a **minimal SwiftUI + WKWebView shell** that loads https://pare.gg. It has no Capacitor, PWABuilder or XcodeGen, and no native tab bar or Debug tab. The Xcode 26 project is made in the Xcode UI with synchronized folders. iPhone + iPad, dark only.

The final bundle ID is `gg.pare.app`, but **until Pare LLC's Developer Program enrollment is approved, it's `gg.pare.app.dev`**. The reason: a bundle ID used with a free Personal Team gets registered to that team and can block Pare LLC from registering it later (Apple forum threads). Phase S does the switch.

The goal is a shell that feels native (no white flash, no rubber-band, safe areas correct, footer hidden). It talks to the web only through a tiny allow-listed bridge and is ready for the later web-side gear/share buttons and universal links.

**Decisions locked (Kobe):**
- **UA token = `Pare-iOS`.** Swift appends `Pare-iOS/<version>` to the default WebKit UA. This matches the live detector `IOS_APP_UA_TOKEN = 'Pare-iOS'` in [lib/platform.ts](lib/platform.ts), so the web needs no change or deploy.
- **External links → SFSafariViewController.** `mailto:`/`tel:` go to the system.
- **Kobe pushes the branch himself** at Mac gates. Claude only makes local commits and never pushes.
- **Project path:** Kobe creates the project in Xcode **at the repo root** (Xcode makes `<repo>/Pare/Pare.xcodeproj` + `<repo>/Pare/Pare/`), then renames the outer `Pare/` → `ios/`. The result is `ios/Pare.xcodeproj` + sources in `ios/Pare/`.
  - **Consequence:** `ios/` must not exist when he renames. So the project is created **before** Claude writes any Swift: P0 → H1 → P1.

## Key behavior (Swift design)

- **PareApp.swift.** `@main struct PareApp: App`, with `@State var shell = ShellState()` (`@Observable @MainActor`: `isOffline`, `showSettings`, `weak var webView`, `retry()`, `navigate(to:)`). `RootView` is a ZStack: `Color("BgDeep").ignoresSafeArea()` → `PareWebView(shell).ignoresSafeArea()` → `OfflineView` when `isOffline`. It adds `.sheet` for SettingsView, `.preferredColorScheme(.dark)`, and retries on `scenePhase == .active` while offline. An `.onOpenURL` stub is left for universal links (Phase W).
- **WebView.swift.**
  - Config and UA: `websiteDataStore = .default()`, so `pare:*` localStorage persists. `applicationNameForUserAgent = "Pare-iOS/<version>"` appends to the default UA and does not replace it.
  - Background: `isOpaque = false`. Background, scroll background and `underPageBackgroundColor` are all BgDeep, so there's no white flash.
  - App-shell rule: `bounces = false`, no bounce on either axis, no UIRefreshControl, `contentInsetAdjustmentBehavior = .never`. The web already uses `viewportFit: 'cover'` + `env(safe-area-*)`.
  - Debugging: `#if DEBUG isInspectable = true`.
  - Navigation policy: https + host ∈ `{pare.gg, www.pare.gg}` → allow. `mailto`/`tel` → system. Other http(s) → SFSafariViewController and cancel. Everything else → cancel. Subframes → allow. `createWebViewWith` applies the same rules and returns nil.
  - Offline: NSURLError notConnected / connectionLost / timedOut / cannotFindHost / cannotConnectToHost / dnsLookupFailed → `isOffline = true`. It **ignores -999**. `didFinish` → `isOffline = false`.
  - `webViewWebContentProcessDidTerminate` → `reload()`, so there's no blank screen after a memory kill.
  - `dismantleUIView` removes the message handler.
  - Uses no KVO and no injected scripts.
- **Bridge.swift.**
  - Origin check: it accepts only messages where `frameInfo.isMainFrame`, the origin is https and the host is in `inAppHosts`. The body must be `[String: Any]` with a `type`.
  - Allowed types:
    - `share {url, title?}`: the URL must be https on pare.gg, and the title is capped at 200 chars. Opens `UIActivityViewController`. **On iPad it sets `popoverPresentationController.sourceView/sourceRect`**; without that it crashes.
    - `haptic {style}`: style ∈ light/medium/heavy/selection/success/warning/error.
    - `openSettings` → shows the sheet.
  - Unknown types are ignored (logged in DEBUG only). Messages are one-way.
  - JS contract: `window.webkit?.messageHandlers?.pare?.postMessage({ type, ... })`.
- **SettingsView.swift.** NavigationStack + List.
  - About and Privacy dismiss the sheet and call `shell.navigate(to: /about | /privacy)` in the main view.
  - Support: `mailto:support@pare.gg`.
  - Version: `1.0 (1)`.
  - Footer: "Not affiliated with the NFL or its teams."
  - Done button, 44pt targets.
- **OfflineView.swift.** BgDeep, `wifi.slash`, "You're offline" with one line of copy, and a Retry button (≥44pt) that calls `shell.retry()`.
- **PrivacyInfo.xcprivacy.** Matches the planned App Store privacy label.
  - `NSPrivacyTracking` false, `NSPrivacyTrackingDomains` empty.
  - `NSPrivacyCollectedDataTypes` has one entry: `NSPrivacyCollectedDataTypeUserID`, with `Linked = true`, `Tracking = false` and `Purposes = [NSPrivacyCollectedDataTypePurposeAppFunctionality]`. Reason: the Fantasy tab sends a Sleeper username to pare.gg.
  - `NSPrivacyAccessedAPITypes` stays empty because the shell uses no required-reason API.
  - The README notes the rules: add CA92.1 if UserDefaults is ever used, and update this file whenever /privacy changes.
- **Config/Info.plist.** `UILaunchScreen { UIColorName = BgDeep }`, `UIUserInterfaceStyle = Dark`, `ITSAppUsesNonExemptEncryption = false`. No ATS exceptions.
